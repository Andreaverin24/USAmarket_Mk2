# DecorFlavor — public experience authority

**Статус:** IMPLEMENTED — ожидает визуальной приёмки владельца.
**Дата:** 18 августа 2026.
**Основа:** `codex/decorflavor-p0-security`; прямое решение владельца — все публичные страницы должны соответствовать уровню главной страницы.

## Scope

- Единый DecorFlavor-интерфейс для каталога, категорий, карточек товара, витрин продавцов и policy-страниц.
- Общие: горизонтальный логотип, тёплая paper-палитра, forest CTA, редакционная serif-типографика, адаптивная 4/3/2/1 сетка, ясные статусы наличия и читаемая мобильная версия.
- Карточка товара: крупное изображение, автор/категория, цена, condition и статус без визуального шума.

## Исследовательские решения

- Премиальный сегмент: спокойная сетка, большие поля, редкий акцентный цвет и прозрачная object information; ориентир — редакционная подача коллекции, а не массовый маркетплейс.
- Не используются декоративные «Buy now», ложная срочность или перегруженные карточки: для уникальных предметов важнее enquiry и provenance.

## Неприкосновенные ограничения

- Сохраняются live API, `Established Lines` offline snapshot, JSON-LD, URL-структура и фильтры.
- Сохраняется P0-flow: reservation → внешний счёт продавца → ручное подтверждение. Платёжные реквизиты и платежи в приложении не появляются.
- Не изменяются security headers, RBAC, CSRF, API/worker, portal и data-pump.

## Контракт проверки

1. `tsc --noEmit --project apps/web/tsconfig.json` проходит.
2. `next build` для `apps/web` проходит.
3. Страницы каталога, товара и `Established Lines` строятся с едиными компонентами без API-мутаций.
