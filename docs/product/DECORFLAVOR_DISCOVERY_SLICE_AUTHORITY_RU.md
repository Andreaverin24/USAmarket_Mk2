# DecorFlavor — authority первого рабочего среза: discovery

**Статус:** ACTIVE — реализация начата 16 августа 2026 года  
**Уровень проектирования:** Level 2 для общего пилота; этот срез не меняет денежные или логистические состояния.  
**Основание:** прямые решения владельца проекта:

- официальное название продукта — **DecorFlavor**;
- нужен запускаемый и тестируемый marketplace, а не статический mock;
- на главной странице обязательны большой поиск, фильтры и случайная витрина товаров со всего сайта;
- оплата внутри приложения не принимается: продавец выставляет счёт клиенту вне DecorFlavor.

## Ближайший вертикальный срез

Гость открывает главную страницу, видит случайную подборку опубликованных товаров, сужает её фильтрами, вводит запрос и попадает в полный каталог с теми же параметрами. Карточка ведёт на существующую публичную страницу товара.

## KNOWN

- В репозитории уже есть Next.js storefront, NestJS API, PostgreSQL-модель каталога, серверный поиск, фильтры, страницы товара и продавца.
- Публичный каталог выдаёт только опубликованные товары активных одобренных продавцов.
- Существующая главная страница использует статический массив и брендинг `THE GUILD`; это не соответствует принятому имени и не использует каталог.

## OWNER DECISION

- Главная страница DecorFlavor должна использовать фактические данные публичного каталога.
- Витрина получает отдельную случайную выборку из всех опубликованных товаров активных одобренных продавцов; это не ограничивается первой страницей каталога.
- Вне приложения нет карточных полей, платёжных ссылок, эквайринга, payout или escrow.

## UNKNOWN / отложено

- Кто имеет право переводить заказ из ожидания внешнего счёта в подтверждённую оплату. До отдельного решения не создаём сущности external invoice, payment confirmation или shipment release.
- Правила доставки, налоги, возвраты, документы и реальные уведомления.

## Scope этого среза

- DecorFlavor branding на публичной главной;
- крупный поисковый ввод;
- фильтры category, price, colour, era, condition и sort;
- случайная сетка реальных опубликованных товаров;
- переход в полный каталог с фильтрами в URL;
- корректные empty/unavailable states.

## Out of scope

- Account, cart, checkout, order, invoice, payment, fulfilment и logistics mutations;
- загрузка или хранение банковских реквизитов/платёжных доказательств;
- внешние вызовы, рассылка, обработка реальных денег;
- изменение существующей модели продавцов и модерации.

## Negative paths

1. API каталога недоступен: главная сообщает о недоступности витрины, не подменяя её ложными товарами.
2. Фильтр не нашёл товары: отображается clear action и ссылка на полный каталог.
3. Товар стал недоступен между витриной и открытием карточки: существующая карточка товара возвращает корректный not-found state; домашняя страница не кэширует результат.

## Контракт проверки

1. `pnpm --filter @atlas/web typecheck` проходит.
2. `pnpm --filter @atlas/web build` проходит.
3. При локальном API с seed-данными главная показывает DecorFlavor, поисковый ввод, фильтры и реальные карточки; отправка поиска формирует `/catalog?...`.
4. При ошибке API нет статического каталога, выдаваемого за живые товары.
